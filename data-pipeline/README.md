# 요리 데이터 수집 스크립트

`backend/src/main/resources/seed/dishes.json`을 만들 때 쓴 수집 단계입니다. 원본 덤프는 용량과 이용 조건 때문에 저장소에 넣지 않고, 정리한 결과(`dishes.json`)만 넣습니다.

## 출처

- 학교 급식 식단: 나이스 교육정보 개방 포털 급식식단정보 API (고등학교만, 점심, 2025년 3월부터 12월)
- 식품 영양 성분: 식품의약품안전처 식품영양성분 데이터베이스 (공공데이터포털)
- 위 두 출처에 없는 요리의 영양 값은 비슷한 요리의 값을 참고한 추정치이며, 시드의 `source` 필드로 구분합니다. 화면에는 "일부 영양 값은 추정치입니다"라고 안내합니다.
- 두 출처의 이용 조건(출처 표시 등)은 배포 전에 다시 확인해야 합니다.

## 실행

인증키는 환경변수로만 읽고 파일에는 적지 않습니다.

```bash
NEIS_API_KEY=... python collect_school_meals.py      # meals_hs.json
NICS_API_KEY=... python collect_food_nutrition.py    # foods.json
```

## 이후 정리 단계

수집한 급식 식단에서 요리 이름을 나누고, 역할(밥, 국, 메인 반찬, 곁들임 반찬, 김치와 절임, 후식)과 주재료, 조리법, 사진 묶음을 분류한 뒤 영양 값을 채워 `dishes.json`으로 정리했습니다. 정리 결과만 저장소에 있으며, 분류 기준은 `DishComposer`의 조합 규칙과 같은 용어를 씁니다.

## 요리별 재료 목록

`dishes.json`의 `ingredients`는 요리마다 양념을 뺀 재료 이름입니다. 공공 API(식품안전나라 조리식품 레시피 DB)는 전체를 받으려면 별도 인증키가 필요해 쓰지 않았고, 기존 레시피 데이터와 이름에서 읽히는 재료를 참고해 직접 작성했습니다. 재료 이름은 `ingredients.json`의 재료 이름과 일치해야 하며, 시드 점검 테스트(`SeedConsistencyTest`)가 이름 일치, 중복, 빈 목록을 확인합니다. `mainIngredients`는 이 목록에서 계산한 큰 분류입니다.

특수 양념(`seasonings`)은 춘장, 두반장, 굴소스처럼 따로 사야 하는 소스만 요리별로 적었습니다. 소금, 간장, 설탕, 마늘 같은 일반 양념은 넣지 않습니다. 재료 선택과 필수 재료 맞추기에는 쓰지 않고 장보기 목록에만 씁니다.
